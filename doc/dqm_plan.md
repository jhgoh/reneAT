### 현장 SPE
- 트리거 앞 pedestal 창(샘플 0–99)의 외딴 단일 펄스를 써요. 높이 ≥ 5 ADC이고, 전하는 피크 −4부터 +12샘플까지 합해요.
- 가짜 비율은 같은 기준을 뒤집은 파형에 적용해서 재요(반대 극성 대조).
  - 4185 A/B 약 0%, 4223 A/B 11%/8%, 4370 A 84%(노이즈 2.9), 4370 B 약 0%
- 가짜 비율이 5%를 넘으면 그 채널의 SPE 값은 표시만 하고 gain flag는 꺼요.
- 절대 gain은 LED 런에서 정해요. 현장 SPE는 문턱 때문에 LED보다 10–20% 낮게 나와서, 런 사이 상대 변화를 보는 용도예요.
- 4223에서 뒤집은 파형에 걸리는 펄스(약 0.9 pC)는 pedestal 창 겹침으로 baseline이 찌그러진 탓으로 추정해요. 아직 확인 전이에요.

## 2. DQM과 프롬프트 분석
- **DQM**: 어떤 런이든 똑같이 만들어지는 그림이에요(위 1의 공통 페이지와 아래 3의 trend). 뮤온 rate, 뮤온 뒤 중성자, 지연 쌍 후보도 모든 런에서 계산되므로 DQM에 넣어요.
- **프롬프트 분석**: 런 종류와 세팅마다 보는 변수가 다르고, 그 결과로 결론을 내려 정식 세팅이나 보정값을 정하는 런이에요.
  - 대상과 정할 것

    | 런 | 보는 것 | 정하는 것 |
    |---|---|---|
    | LED(HV 스캔, SPE 런) | 광전자 수, SPE fit, gain vs HV. 기록 1008샘플, LED 동기 트리거(ch3), 펄스 약 366번 샘플 | PMT gain, 운전 HV |
    | source | 피크 fit(위치·폭), 가까운 background 런 빼기, 위치별 A/B 비, 소스 rate | 에너지 척도, 분해능, 위치 응답 |
    | veto 테스트 | 패널별 효율·문턱, 내부 검출기와의 동시 신호 | veto 문턱, 패널 맵 |
    | 레이저 | (지금은 다루지 않음. 측정 조건 관리가 어려웠던 데이터. 새로 측정하면 추가) | 선형성, 포화 |
    | 그 밖의 시험 런 | 시험마다 | 시험마다 |

  - 공통 DQM 페이지는 이 런들에도 자동으로 그려요. 설정이 정상인지 확인하는 용도예요.
  - 분석은 `analysis/<종류>/` 아래 스크립트로 두고, 런 목록과 창 설정을 인자로 받아요. 결과는 런 하나가 아니라 런 묶음(HV 스캔 전체, 선원별 피크 전체)으로 나와요.
  - 정기적으로 받는 source 런은 run sheet 종류로 골라 자동으로 돌릴 수 있어요.
  - 결론으로 정한 값(운전 HV gain, 선원 피크 위치, 패널 효율)은 기준값으로 남겨요. DQM trend가 이 값을 읽어 시간 변화를 그려요.
  - 위치: `analysis/<종류>/`(`led/`, `source/`, `veto/`, `laser/`). 지금 있는 것은 `analysis/led/gain.py`

### 이름 정리
- **프롬프트 재구성(prompt reco)**: 모든 런에 돌리는 프롬프트 재구성예요. 지금의 `prompt` 모듈과 `reneat prompt` 명령이고, 파형을 읽어 ntuple과 subrun 히스토그램을 만들어요.
- **프롬프트 분석**: 위의 런 종류별 분석이에요. 재구성 출력을 읽어서 결론을 내요.
- 코드 이름은 정리할 때 맞출 예정이에요. 예: 모듈 `prompt` → `promptreco`, 분석은 `analysis/`.

### 신호선 상태 보기 (2026-06-14 PMT A 반복 펄스 같은 문제)
원칙: 자동 판정 코드를 만들지 않고, 사람이 보고 판단할 수 있게 펄스 모양을 보여 줌. 어느 채널이 문제인지 미리 가정하지 않고 A, B를 똑같이 그림.

- 지금 DQM: 런 안에서 subrun의 rise가 런 중앙값에서 5샘플 넘게 벗어나면 flag(4232 subrun 10–17은 이걸로 잡힘). 런 전체가 나쁘면 안 뜸(4370). 이 flag는 참고용으로만 둠
- 더할 그림
  - [ ] **평균 펄스**: 채널별, 높이 구간별, 앞쪽 가장자리 정렬. 기준 펄스(정상 기간)와 이전 런 평균을 겹쳐 그림. 선형·log 두 가지
  - [ ] **펄스 퍼짐(RMS, 분위수 띠, 겹쳐 그리기)**: 같은 정렬·정규화로 샘플마다 평균 주위 RMS, 5/16/50/84/95% 띠, (정규화 진폭 × 시간) 2D 히스토그램(오실로스코프 잔상처럼). 모양이 섞이면 해당 시간에서 RMS가 커지고 2D 그림에 갈래가 따로 보임(4232 A subrun 5,7+12,14: +75·+135 ns에서 RMS 0.3, 정상 0.01–0.12). 4370 A처럼 런 전체가 바뀐 경우도 반복 펄스 크기가 펄스마다 달라 RMS가 전 구간 0.15–0.2로 큼. 그래도 무엇이 바뀌었는지는 평균 펄스의 기준 비교로 봄. 앞쪽 가장자리의 RMS 봉우리는 2 ns 정렬 흔들림 탓이라 정상. pedestal 구간 RMS를 노이즈 기준선으로 같이 표시
  - [ ] **시간에 따른 펄스 모양**: 가로축 런 안 시간(subrun과 무관한 일정 이벤트 묶음), 세로축 앞쪽 가장자리 뒤 시간, 색은 정규화한 평균 파형. 모양이 바뀐 순간이 띠가 바뀌는 것으로 보임(4232 subrun 9–18 같은 것)
  - [ ] **비슷한 펄스끼리 묶어 보기**: 정규화한 펄스를 몇 가지 대표 모양으로 묶어서(예: 대표 모양 4–6개) 각 묶음의 평균 파형과 비율을 보여 줌. 정상 런은 한 모양이 대부분, 겹친 펄스·반사·포화는 따로 묶여 보임
  - [ ] **개별 펄스 예시**: 무작위 몇 개와, 묶음마다 몇 개
  - [ ] **두 채널 같은 이벤트 비교**: A 피크 − B 피크 분포, log10(A/B) 분포와 시간 변화. 숫자 판정 없이 분포만
- 프롬프트 재구성에 필요한 것: 이벤트 묶음별 평균 파형(채널별, 높이 구간별, 합과 제곱합을 저장해 RMS도), (정규화 진폭 × 시간) 2D 히스토그램, 대표 모양 묶음 결과, 예시 파형 몇 개 저장
- 나쁜 구간 목록은 그림을 보고 사람이 정해서 파일로 관리함(채널, 시작·끝 엔트리 또는 시각, 이유). 분석은 이 목록을 읽음
  - 구간을 찾을 때 참고할 수 있는 것: 같은 이벤트의 A−B 피크 차는 정상 0.2–1.2%, 4370의 A 문제 상태 97%로 차이가 큼(AmBe 4223에서도 200개 묶음 최대 2.5%)
  - 깨끗한 이벤트를 고를 때 검사 대상 채널의 양(그 채널의 `PedMax` 등)으로 고르면 치우침(4232에서 나쁜 구간이 1/8로 줄어 보임). 시간 간격, veto, 포화처럼 채널과 무관한 조건만 씀

## 5. 프롬프트 재구성(지금의 `prompt` 모듈)와 DQM의 역할 나누기
- **프롬프트 재구성**: subrun마다 PRD 파형을 한 번 읽어요. 파형이 있어야 하는 계산은 모두 여기서 해요.
  - 이벤트별 양(ntuple)
  - subrun 히스토그램과 요약
- **DQM과 프롬프트 분석**: 프롬프트 재구성 출력만 읽어요. 파형을 다시 읽지 않아요.
  - 런 하나 안의 그림, flag
  - 여러 런을 함께 쓰는 것: background 빼기, 기준 런 비교, trend

### 프롬프트 재구성에 더할 것
- [ ] 뒤집은 파형 단일 펄스 히스토그램(SPE 가짜 비율)
- [ ] subrun 평균 파형(채널별, 높이 구간별, 앞쪽 가장자리 기준 정렬): 펄스 모양, A·B 시간
- [ ] 트리거 펄스 뒤 창의 펄스 수와 시간 분포: afterpulse. 앞 트리거와의 시간 간격별 단일 펄스 수: dark rate와 상관 펄스 구분
- [ ] 기록 길이나 트리거 설정이 다른 런(LED 등)에서 프롬프트 재구성가 깨지지 않게 하기. 측정용 창은 프롬프트 분석에서 정해요
- [ ] prompt 출력 버전 번호: DQM이 오래된 출력을 알아보고 다시 돌릴지 판단

### 프롬프트 재구성 출력만으로 되는 것 (ntuple에 이미 있음)
- DQM: 뮤온, 지연 쌍, 포화 (아래)
- 프롬프트 분석: source 피크 fit, A/B 비(`Qsum_c`, `Qgm`), 소스 rate, background 빼기(다른 런의 prompt 출력을 같이 읽어서)
- 뮤온 rate, 뮤온 뒤 중성자, 지연 쌍: `NVeto`, `DtPrevMuon`, `DtPrevFADC`
- 포화: `Height_c`, `Sat_c`
